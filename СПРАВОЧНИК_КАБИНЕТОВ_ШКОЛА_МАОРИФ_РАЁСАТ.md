# SmartMaktab — отдельные кабинеты школы, маориф и раёсата

**Главное правило разработки: одна должность или специальность — один собственный HTML-файл.** Например, у учителя школы, мушовира по таджикскому языку и литературе и мушовира по информатике три разные страницы. Нельзя заменить их одним универсальным файлом `cabinet.html?role=…`. Общие компоненты, стили, переводы и проверку доступа можно переиспользовать. Если один человек отвечает за несколько направлений, у него один аккаунт и ссылки на несколько назначенных кабинетов, а не один общий кабинет со всеми полями.

Это проектный справочник, **не утверждённое штатное расписание**. Названия и цепочку подчинения органов маориф и раёсата, должности конкретных сотрудников и их права нужно уточнить по территории. В демо уже созданы 54 отдельных файла. Пять страниц наполнены вымышленными примерами (директор, учитель, библиотекарь, мушовир по информатике и раёсат), остальные содержат анкеты с полями по должности, но пока без рабочих документов и полномочий. Все проверки — только на вымышленных данных.

## 1. Навигация и уровни

- **Муассиса (новый старт):** уровень → основная должность из 20 пунктов → до 10 дополнительных → имя и фамилия в основной анкете → проверка унаследованных данных → отдельный кабинет → анкетирование по работе → поиск и выбор школы МТМУ № 1–88. Отдельный каталог снят с публикации: используйте выбор должности на стартовом экране.
- **Маориф:** свой орган → должность или направление → для методистов **«Мушовирон» → специальность** → отдельный кабинет. В кабинете — закреплённые школы и сведения только по своему направлению.
- **Раёсат:** свой орган → подтверждённая должность → отдельная страница. Сводки по закреплённым территориям и учреждениям, без автоматического доступа ко всем школам страны. Не считаем, что во всех регионах органы устроены одинаково.

Главный `index.html` остаётся точкой входа. Выбор профиля не даёт доступа: сервер подтверждает учреждение, должность, территорию и предмет/направление. Страницы каталога и входа — дополнительные и не заменяют отдельные файлы кабинетов.

## 4. Пример: что видит мушовир по информатике

1. Список только закреплённых школ; по каждой — число **разных действующих учителей информатики** за выбранный период. Если учитель ведёт несколько классов в одной школе, он считается один раз для этой школы и этого предмета. «Нет данных» отличаем от `0`.
2. По выбранной школе — классы, планы работы и статусы документов (например, «не представлен», «на проверке», «проверен»); детали и история действий открываются только в тех категориях, которые разрешены его назначением. Список учителей поимённо — только после отдельного согласования необходимости, не по умолчанию.
3. Переключение между школами не даёт доступ к русскому или английскому языку, бухгалтерии, психологическим материалам или ученическим сведениям. У мушовира по русскому — та же схема, но другая страница, другой предмет и свои шаблоны.
4. Просмотр, комментарии, согласование и выгрузка — разные права. На первом этапе консультанты только читают разрешённые синтетические сводки и статусы; действие «утвердить» не появляется автоматически. Для документов учитываем тип, статус и кому они адресованы. Объединение должностей в интерфейсе не расширяет права.

## 5. Порядок разработки

1. Создать **справочник маршрутов** и отдельные HTML-каркасы для всех перечисленных кабинетов в существующем проекте. Каркас — название, путь назад, отметка «не настроено», никаких придуманных полей или прав. Сохранить существующее демо. Проверить порядок «Муовини ҳарбӣ → Созмон» и «Роҳбари синф → Раиси Шӯрои духтарон».
2. Добавить выбор школы/органа и должности/направления, затем вымышленное наполнение для первого связанного примера: **учитель информатики школы → мушовир по информатике маориф → сводка раёсата**. Проверить, что три страницы физически разные и поля на них разные. Показать соседнее предметное направление для проверки, что данные не смешиваются.
3. Согласовать реальные названия, список предметов, категории документов и правила доступа, прежде чем подключать облачные данные. Затем проверять API на синтетике: чужая школа, чужой предмет, чужая территория и закрытая финансовая/психологическая категория не раскрываются, даже если открыть прямую ссылку.
4. Наполнять остальные страницы небольшими группами. По каждому кабинету отдельно утверждать поля, шаблоны, права и показатели. Новую должность добавлять отдельным HTML-файлом и записью в справочнике — без переписывания главного `index.html`.
