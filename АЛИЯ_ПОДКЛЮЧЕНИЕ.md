# «Алия» Kitobkhona в SmartMaktab

## Без ключей (по умолчанию)

Из `index.html` и в обычной веб-версии доступны шесть действий: выжимка, слова и термины с примерами из текста, перевод при наличии поддерживаемой локальной языковой пары, задания, черновик плана урока и сохранение в заметки. Можно выбрать страницы; затем результат связан с этим диапазоном. Локальный результат использует слой PDF и не исправляет произвольно имена и факты. Для скана без слоя текста нужен OCR. После первого открытия PDF байты держатся в памяти вкладки; при скачивании повторно сеть не используется. Кеш очищается при закрытии вкладки и ограничен 150 МиБ / 6 книг.

## Серверный режим — только через ваш действующий шлюз Kitobkhona

Адаптер использует оригинальные маршруты Kitobkhona — `POST /v1/chat` и `POST /v1/vision`. В SmartMaktab ничего не подключено к облаку по умолчанию. Понадобится **HTTPS-адрес вашего шлюза Алия** (без `/v1/chat` в конце). В PowerShell из папки SmartMaktab:

```powershell
$env:SMARTMAKTAB_ALIYA_GATEWAY_URL = 'https://АДРЕС-ВАШЕГО-ШЛЮЗА'
py -3 scripts\preview.py --with-aliya --open
```

- Если **ваш шлюз** требует Bearer‑токен, задайте его в `SMARTMAKTAB_ALIYA_GATEWAY_TOKEN` в том же серверном процессе. Не вписывайте его в HTML, JavaScript, архив, GitHub или чат.
- Ключ **провайдера модели** устанавливается **на хостинге самого шлюза Kitobkhona**, в разделе **Secrets / Environment Variables**, например `GEMINI_API_KEY`, если там выбран Gemini. Если рабочий шлюз уже настроен, новый ключ провайдера обычно не нужен. Ключ Supabase для этой задачи не нужен.
- В читалке появится переключатель **«Алия Kitobkhona»**. Он по умолчанию выключен. При подтверждённом запуске задачи отправляется только выделенный фрагмент PDF; для скана без текста — изображение одной выбранной страницы и затем распознанный текст. Не отправляйте документы с персональными данными. Нет опроса шлюза при старте, автосинхронизации или повторных запросов при ошибке.
- Этот режим запускается только на `127.0.0.1`, не доступен с телефона через внешний адрес и не рассчитан на общедоступный API. Для Android/веба потребуется отдельная HTTPS-интеграция с авторизацией, лимитами и политикой данных. Прямые `file://` и статический PWA не хранят секреты и используют только локальный режим.

Интеграция проверяется с синтетическим шлюзом. Результат реального облачного OCR и генерации зависит от вашей конфигурации и квот. Штатные функции нативных приложений Kitobkhona и соцфункции не переносились.
