# SmartMaktab + Kitobkhona: обновлённый план

**Базовое решение:** развиваем существующий SmartMaktab. Не заменяем его сайтом Kitobkhona и не подключаем серверы Kitobkhona для работы школьных форм или чтения книг. Таджикский остаётся основным языком, русский доступен по выбору. Сохраняем физические кабинеты, две заставки, ночной режим и указание правообладателя. На этапе проверки — только вымышленные школьные данные.

## 1. Что проверено в архиве и в открытом доступе

- `kitobkhona.txt` — ZIP с 435 записями. Изучены каталог, читалка, кэш, код «Алия», фоновые задания и отчёты о проверках. Это обзор архитектуры и проверка пригодности отдельных модулей, а не запуск всего архива.
- Публичные репозитории, указанные в архиве: [sharipovip/kitobkhona](https://github.com/sharipovip/kitobkhona) — клиент и компоненты; [sharipovip/books](https://github.com/sharipovip/books) — книги. Основные учебники находятся в отдельном репозитории, не в ZIP. В ZIP есть примеры планов уроков в DOCX/PDF.
- `books.json` задаёт категории и папки; в приложенном снимке `search-index.json` — **587 записей, из них 224 в категории учебников**, с папками всех 11 классов. Это количество записей снимка, а не гарантия полноты, актуальности или доступности всех документов. В записях есть путь, имя и категория, но нет надёжных отдельных полей предмета, языка издания, года и применимости. Например, в архивном индексе в папке 5-го класса не найдено название «Математика» / «Риёзӣ». Не подменяем отсутствующую книгу изданием для другого класса.
- Выполнена выборочная проверка трёх учебников через статический источник `sharipovip/books`: «Математика 1», «Технологияи иттилоотӣ 5» и «Алгебра 11». Все три вернули фрагмент файла по HTTP Range (`206`) с PDF-сигнатурой. Все 224 файла не проверялись. Открытая ссылка не равна разрешению на перепубликацию; до подтверждения прав используем ссылки на источник, не копируем весь фонд в SmartMaktab и не включаем PDF в дистрибутив. Офлайн-загрузку конкретных изданий включаем после подтверждения условий использования.
- В архиве есть PDF.js с worker и отдельная логика PDF-кэша; их можно взять за основу после проверки лицензий и зависимостей. У полной читалки, общего `config.js` и страниц Kitobkhona есть связи с пользовательским API, избранным и сеансами чтения. Их целиком не переносим.
- В архиве есть клиент «Алия» (шаблоны, задачи, PDF) и Python gateway (чат, анализ, генерация и конвертация документов, изображения, речь). Отчёт архива указывает, что API в живом окружении не проверялся. Архив также содержит периодические workflow для новостей, очистки и Supabase keepalive. Эти задания, общую авторизацию и конфиги из архива не копируем. Сами облачные сервисы не запускались и не настраивались.

## 2. Этапы внедрения

### Этап 1 — кабинет учителя и учебник по паре «класс — предмет»

1. Шапка показывает текущую школу и должность. В профиле учителя: **«Синфҳое, ки дарс медиҳед» → «Рақами синф» → «Ҳарфи синф» → «Фан»**. В одной школе возможны разные предметы в одном классе; точный повтор запрещён. При нескольких школах список свой для каждой. Старые сохранённые классы не теряются: для них нужно отдельно подтвердить предмет, а не подставлять информатику.
2. На рабочем столе **«Синфҳо ва фанҳои ман»**. В строке, например, `5А · Технологияи иттилоотӣ`, кнопка **«Нақшаи дарс»** открывает план уже с этой парой. Кнопка **«Китоби дарсӣ»** показывает совпадающие учебники. Печатный план получает название выбранного предмета, а не фиксированное значение. Если учитель выбрал класс в форме вручную, доступны только его предметы в этом классе и школе.
3. Создаём версионированный статический индекс: идентификатор книги, класс или диапазон классов, идентификатор предмета, язык/год (только подтверждённые), путь в публичном источнике и статус проверки. Делаем справочник предметов RU/TG и ручные соответствия для неоднозначных названий; не выводим язык книги из языка интерфейса. Буква класса не влияет на выбор учебника, но важна для плана и отчётности. Для нескольких изданий показываем список с пометками. Если совпадения нет, показываем «Китоби мувофиқ ёфт нашуд», не выбираем другой класс. Предпочтение учителя учитываем в пределах его школы и пары.
4. В первом выпуске автоматически появляется **карточка доступной книги**, а не загрузка PDF. Открытие — по кнопке у статического источника. После проверки PDF.js изолируем небольшую читалку только с просмотром страниц, масштабом и, где есть текстовый слой, поиском. Локальная позиция чтения не отправляется на сервер. В офлайн-просмотрщике Arena каталог встраиваем, внешние PDF открываются отдельной ссылкой при наличии сети; полноценное кэширование проверяем в браузере/PWA, не обещаем его внутри файлового iframe.
5. Офлайн (отдельный шаг): только выбранная пользователем книга, если её можно сохранять. Показываем размер, свободное место и удаление. Не кэшируем весь фонд и не кладём книги в обязательный набор service worker. При переполнении кэша или недоступности ссылки остальные инструменты продолжают работать.

**Приёмка:** у одного учителя два предмета в одном классе и две школы; переключение не смешивает данные. Есть случаи с одним изданием, несколькими, отсутствующим учебником и ошибкой источника. При открытии кабинета число запросов к Render, Neon, Supabase и PDF равно нулю для локального сценария. Сохранение разрешённой книги в обычном браузере проверяется в отдельном офлайн-тесте.

### Этап 2 — недельное расписание, качество образования, документы

- **«Ҷадвали дарсҳо».** Недельная сетка для класса на базе готовой дневной формы. Для каждого урока: день недели, начало и конец, класс, предмет, учитель, кабинет. Предупреждать о наложении для одного класса, одного учителя или одного кабинета в пределах школы; соседние уроки с совпадающим временем конца и начала не конфликтуют. Проверка разных школ возможна только при доступе к их расписаниям и подтверждённой общей учётной записи учителя — не угадывать по ФИО. Печатать день или неделю.
- **«Сифати таҳсилот».** Сводная таблица `Чоряки 1 | Чоряки 2 | Нимсолаи 1 | Чоряки 3 | Чоряки 4 | Нимсолаи 2 | Солона`. Для каждого периода видны свои исходные сводные числа и коэффициенты. `—` — нет данных, `0` — реально введённый ноль. Не выводить годовой процент простым средним из процентов разных четвертей. Среднее по предмету из предыдущего прототипа показывать отдельно с пояснением метода; официальные формулы и критерии согласовать до использования в школе. Индивидуальный учёт оценок не добавляем.
- **«Ҳуҷҷатҳо».** Разделить **«Шаклҳои корӣ»** и **«Намунаҳо»**. Перед печатью показывать школу и применимые поля: класс, предмет или период. Неутверждённый шаблон маркировать **«Тасдиқ нашудааст»**. Юридические реквизиты не выдумывать. Когда поступят пилотные DOCX + JSON от локального агента, сверить поля и подстановку на двух условных школах, проверить печать. Только после этого применять формат к другим документам.

**Приёмка:** проверяются три вида конфликта расписания, корректность граничного времени, печать выбранного дня/недели, пустые периоды и настоящий ноль в отчёте, правильная школа при печати. Печатные формы генерируются локально без API.

### Этап 3 — кабинет библиотекаря

- Отдельно от электронных учебников сделать учёт **физических экземпляров**: название, инвентарный номер или экземпляр, доступное количество, дата выдачи, крайний срок, возврат, список просроченных. Переиспользовать приёмы интерфейса из «Мактаби Муосир», не переносить его SQLite и реестр учеников. Электронная книга из публичного репозитория не уменьшает остаток бумажных экземпляров.
- Сначала — местная проверка на вымышленных записях: нельзя выдать один экземпляр дважды и нельзя дважды оформить один возврат. Реальные получатели и параллельная работа нескольких пользователей — только после разрешённых назначений, серверной транзакционной проверки и тестов RLS.

### Этап 4 — сводки «Директор → Маориф → Раёсат»

- Начать в отдельном **Supabase Dev**. Директор готовит сводку своей школы, затем явно отправляет на проверку. Статусы: **«Пешнавис → Ба баррасӣ → Тасдиқ шуд / Барои ислоҳ»**. Для возврата на исправление — комментарий; при повторной подаче — отдельная версия. Раёсат видит сводку в пределах назначенной территории; имена учеников и персональные документы в сводку не отправляются.
- Доступ по проверяемому сервером назначению, школе и территории. RLS не доверяет номеру школы из интерфейса или URL. Тесты: своя и чужая школа, чужая территория, отозванное назначение, запрещённый переход статуса, повторная отправка после сбоя. Переносим проверенные приёмы аудита и идемпотентности из SmartMaktab Dev, **не** переносим старый экспериментальный опрос раз в 5/30 секунд. Для отчётов — чтение по входу в раздел и по **«Навсозӣ»**, запись только по явной команде.
- Никаких миграций, включения процессов или привязки к боевому проекту без проверки Dev и отдельного подтверждения. Если Dev недоступен, локальная работа с формами остаётся доступной, но приложение не показывает «отправлено» без подтверждения сервера.

### Этап 5 — «Алия» по кнопке, а не в фоне

- Сначала без сервера: локальные шаблоны плана, подсказки по структуре, экспорт и работа с согласованными бланками. Из кода «Алия» берём отдельные операции после теста; не подключаем весь gateway ради простого заполнения полей.
- Облачный ИИ — опционально и по отдельному одобрению. Первая версия: одна команда **«Кумак бо нақшаи дарс»** для вымышленной или обезличенной темы. Не отправлять ученические карточки, справки, ФИО или закрытые документы и не хранить запросы с персональными данными в логах. Один явный запуск, ограничение размера и частоты запросов и дневного бюджета на стороне сервера, конечный таймаут, понятная ошибка при холодном старте, без скрытых повторов и фоновой генерации. Отмена со стороны клиента не гарантирует остановку уже начавшегося вычисления на сервере: отдельно проверяем отмену в gateway и у провайдера. Голос, изображения и другие тяжёлые режимы выключены по умолчанию.

## 3. Правила экономии бесплатных ресурсов

| Сценарий | Что обращается к сети |
|---|---|
| Старт, анкеты, учебный план, предварительный просмотр, печать, выбор книг | Нет обращений к Render, Neon и Supabase для местного процесса. Каталог — небольшая статическая часть сборки. |
| Нажатие «Открыть книгу» | Прямой запрос к статическому источнику книги. Нет прокси через Render/Neon/Supabase. Нет предзагрузки PDF и обложек при запуске. |
| Доступ к серверным сводкам | Только необходимые Auth/RLS и запросы по действию пользователя; штатные запросы Auth проверяются отдельно и не используются как keepalive. Нет таймера, Realtime или синхронизации в скрытой вкладке. |
| «Алия» (если включена отдельно) | Запрос только после явного запуска команды. Без автоматического `/health`, загрузки списка моделей при старте, удержания сервера от сна, регулярных cron и постоянных соединений. |
| Обновление каталога | Ручная проверка и выпуск новой версии индекса, не отдельный запрос от каждого учителя при открытии кабинета. |

**Контроль:** браузерные тесты перехватывают запросы к внешним доменам и проверяют отсутствие незапрошенных сетевых обращений в простое, в видимой и скрытой вкладке. Перед облачным пилотом смотрим фактические лимиты и счётчики в кабинетах владельца. Не обещаем непрерывную доступность бесплатных тарифов и не мешаем штатному засыпанию сервисов. Если позже потребуется сохранить доступность отдельного компонента, сначала обсуждаем варианты и стоимость.

## 4. Очерёдность ближайшего выпуска

Начать с **«Устод: школа → класс → предмет → план урока + карточка учебника»** и небольшого проверенного набора предметов. Для испытания выбрать материалы, где книга точно найдена, и один намеренный пропуск. После проверки добавить недельное расписание, сводную таблицу и разделение документов. Не переносить чат, ленту, конкурсы или весь ИИ-стек до появления согласованной школьной задачи. Архив исходного проекта не заменяется. По этому плану в текущем обзоре код SmartMaktab и облачные настройки не менялись.
