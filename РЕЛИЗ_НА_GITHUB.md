# SmartMaktab — подписанный EXE / APK / AAB

Это исходники и ручной конвейер, **не** три готовых установщика. Сборка не выкладывает ничего на сайт, в GitHub Releases или Google Play автоматически. Публикуйте только после установки и проверки. Не загружайте в GitHub архив ключей, данные школ, пользовательские формы, `.env` или серверную конфигурацию.

## 1. Загрузить исходники

1. Создайте приватный репозиторий GitHub. Распакуйте ZIP исходников; `.github/workflows/signed-release.yml` должен оказаться **в корне репозитория** относительно `.github`, не внутри лишней папки. Проводник может скрывать имена с точкой; надёжнее использовать Git. Из распакованной папки: `git init -b main`, `git add -A`, `git status --short`. Просмотрите список: JKS, PFX, паролей или реальных данных там быть не должно. Затем `git commit -m "SmartMaktab signed release pipeline"`, `git remote add origin АДРЕС_ВАШЕГО_РЕПОЗИТОРИЯ`, `git push -u origin main`.
2. В репозитории: **Settings → Secrets and variables → Actions**. Для каждого поля нажмите соответствующий **New repository secret** или **New repository variable**. Дайте доступ к изменению ветки и ручной сборке только доверенным участникам; проверяйте изменения workflow. Не вводите пароли в поля запуска workflow и не отправляйте их в чат. Разрешите используемые Actions в политике репозитория. Workflow виден после появления в ветке по умолчанию.

## 2. Android: один набор настроек для выбранной подписи

| Тип | Имя | Откуда взять |
|---|---|---|
| Secret | `ANDROID_KEYSTORE_BASE64` | Однострочный Base64 **JKS** с приватной записью, из локального набора владельца. |
| Secret | `ANDROID_KEYSTORE_PASSWORD` | Пароль JKS. |
| Secret | `ANDROID_KEY_ALIAS` | Alias записи, `smartmaktab-release` при создании нашим скриптом. |
| Secret | `ANDROID_KEY_PASSWORD` | Пароль записи (может совпадать с паролем JKS). |
| Variable | `ANDROID_CERT_SHA256` | SHA‑256 **сертификата** записи, не хеш файла JKS; формат с `:` или без. |

Для нового проекта приложение имеет ID `tj.smartmaktab.app`. Проверьте свободен ли он и корректен ли для существующего приложения до первой поставки. Для APK выбирайте ключ, которым уже подписаны прямые установки. Для AAB нужен ключ, который Play Console принимает как **upload key**. Если у вас эти ключи разные, используйте изолированные окружения/репозитории с отдельным набором этих имён и не переключайте ключи вслепую. APK из Play подписывает Google **app signing key**: если этот сертификат отличается от сертификата прямого APK, такие установки не обновляют друг друга; удаление старой версии может привести к потере локальных данных. AAB в Play Console загружается вручную, с увеличением `versionCode` относительно всех ранее отправленных сборок. Канал внутреннего тестирования Play проверяет подписанный релиз и не является debug-режимом конвейера.

## 3. Windows: один из двух доверенных вариантов

Общие **Variables**: `WINDOWS_SIGNING_MODE` = `azure` (предпочтительно) или `pfx`; `WINDOWS_SIGN_PUBLISHER` = точное простое имя издателя из сертификата (`SimpleName`), без догадок. После проверки подписи оно должно совпасть с владельцем обоих PE-файлов.

| Режим | Тип | Имя | Источник |
|---|---|---|---|
| azure | Variable | `WINDOWS_SIGN_ENDPOINT` | Региональный URL из Azure Artifact Signing: `https://<region>.codesigning.azure.net`. |
| azure | Variable | `WINDOWS_SIGN_ACCOUNT` | Имя учётной записи Artifact Signing. |
| azure | Variable | `WINDOWS_SIGN_PROFILE` | Имя профиля сертификата **Public Trust**. |
| azure | Secret | `AZURE_TENANT_ID` | Tenant ID Entra ID. |
| azure | Secret | `AZURE_CLIENT_ID` | Application (client) ID service principal. |
| azure | Secret | `AZURE_CLIENT_SECRET` | **Value** клиентского секрета (не его ID). |
| pfx | Secret | `WINDOWS_CERT_BASE64` | Base64 легитимного, доверенного PFX, если экспорт разрешён CA. |
| pfx | Secret | `WINDOWS_CERT_PASSWORD` | Пароль PFX. |

В Azure назначьте этому principal роль подписи у профиля; private/test trust не пройдёт проверку на обычном runner. Не используйте админский ключ. Проследите за сроком секрета. При PFX получить Base64 можно локально: `[Convert]::ToBase64String([IO.File]::ReadAllBytes('C:\PRIVATE\release.pfx'))`; не используйте общую сессию и очищайте буфер/вывод. Если сертификат на токене/HSM, этот PFX-режим к нему не применим. Подпись и отметка времени не гарантируют отсутствия предупреждений SmartScreen при первой установке.

## 4. Запуск и проверка

1. **Actions → SmartMaktab — подписанный релиз → Run workflow**. Выбрать `EXE`, `APK` или `AAB`; `release_version` вида `1.0.0`, Android `android_version_code` — положительное целое, увеличивать. За запуск работает один job/один формат.
2. Отсутствующие настройки останавливают запуск до сборки. Битые либо несовпадающие подписи блокируют шаг загрузки. При успехе открыть запуск → **Artifacts** → скачать ZIP; внутри выбранный файл и `SHA256SUMS.txt`, срок хранения 14 дней. ZIP Actions сам не является установщиком.
3. EXE: Windows x64, проверить «Цифровые подписи» или `Get-AuthenticodeSignature .\SmartMaktab-…exe`; выполнить установку под обычным пользователем, затем первый вход и чтение. APK: проверить `apksigner verify --print-certs файл.apk`, сверить SHA‑256 сертификата, установить только после сверки. AAB: вручную отправить в закрытый/внутренний трек своего приложения, проверить обновление и сертификаты Play Console. SHA‑256 файла отдельно сравнить с `SHA256SUMS.txt` (`Get-FileHash` или `sha256sum`).
4. Для Windows/Android на устройстве: старт без сети, переход по «Оғоз» и возврат, профиль классов, ночной кабинет / дневной PDF, сохранение открытой книги, «Файлы», отмена выбора, отказ в разрешении камеры и микрофона, отсутствие запроса уведомлений на первом старте. Нативная оболочка Android создаёт канал, но не отправляет уведомления и не запрашивает разрешение без функции. В выбор файлов Android не входят blanket storage permissions; камера/микрофон задействуются только страницей своей оболочки при соответствующем действии, отдельного школьного медиаинтерфейса пока нет. Windows открывает выбранный файл штатной программой; нативная отправка реализована на Android, Windows Share UI и отдельный UX уведомлений не подключены. Для Android печать через системный диалог отдельно не подключена: веб-версия сохраняет день/неделю; Android PDF/DOCX сохраняет через системный выбор папки. Обновления Play могут потребоваться при новых разрешениях, API или правилах.

## Текущее состояние

Настройки и защитные проверки подготовлены. Первый подписанный выпуск с вашим реальным сертификатом, проверка Windows/Android на устройстве и проверка Google Play остаются отдельными обязательными шагами. Функции Supabase Dev и шлюз Алии не публикуются этим конвейером. Локальные заметки и сохранённые файлы не синхронизируются между устройствами.
